## La preuve : l'agent utilise le catalogue

**Question posée** (langage naturel) :
> « Quel est le CA des clients actifs en 2025 ? »

**Raisonnement de l'agent** (extrait, verbatim) :
> "I've also double-checked the specific rules provided: *'Le chiffre d'affaires (CA)
> se calcule TOUJOURS avec SUM(mnt_ht)'* — this crucial metadata dictates how the
> revenue is calculated. *'Un client actif est un client dont dim_client.statut = A'*
> — this definition is fundamental […] and was correctly applied."

→ L'agent cite **explicitement les descriptions du catalogue** pour construire sa requête.

**SQL généré par l'agent** (réel) :
```sql
SELECT
  SUM(fact_ventes.mnt_ht) AS chiffre_affaires
FROM `quittes-83211.retail_poc.fact_ventes` AS fact_ventes
INNER JOIN `quittes-83211.retail_poc.dim_client` AS dim_client
  ON fact_ventes.client_key = dim_client.client_key
INNER JOIN `quittes-83211.retail_poc.dim_date` AS dim_date
  ON fact_ventes.date_key = dim_date.date_key
WHERE dim_client.statut = 'A'
  AND dim_date.annee = 2025;
```

**Réponse en langage naturel** (réelle) :
> « En 2025, le chiffre d'affaires total réalisé auprès des clients actifs s'élève à
> **2 864 226,45 € HT**. Cette mesure s'appuie uniquement sur les clients ayant le
> statut actif ('A') et sur le montant hors taxe (mnt_ht) cumulé pour les ventes de
> l'année 2025. »

## Notes d'exécution (pièges rencontrés & corrigés dans le repo)

1. **Facturation requise** : un projet BigQuery *sandbox* refuse les requêtes DML
   (`INSERT`) et les scans Dataplex / l'agent Gemini. Il faut lier un compte de
   facturation (`gcloud billing projects link …`).
2. **FLOAT64 → NUMERIC** : BigQuery ne convertit pas implicitement ; les valeurs
   monétaires sont `CAST(... AS NUMERIC)` dans `sql/02`.
3. **Limite de débit métadonnées** : trop d'`ALTER TABLE SET OPTIONS` d'affilée
   déclenchent *« too many table update operations »*. Les descriptions sont donc
   posées **inline dans le `CREATE TABLE`** (`sql/01`), 1 opération par table.
4. **Onglet « Data Profile » de BigQuery vide** : normal, notre scan ne *publie* pas
   ses résultats vers BigQuery. Les résultats sont dans la console Dataplex
   (Govern → Data profiling & quality). Pour publier, recréer le scan avec l'option
   de publication activée.
